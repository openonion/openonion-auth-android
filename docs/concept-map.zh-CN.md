## 📋 OVERVIEW

- 网站签发的 TOTP secret 是一种“持有者能力”，不是人的身份证明。
- SLIP 是从一个根秘密派生隔离密钥的树，不是动态验证码算法。
- 签名证明某个密钥持有者发出了请求；加密负责不让别人看见 secret。
- 第一阶段只有人和手机；Agent Approve 是第二阶段。
- App 不应保存 OpenOnion 账户根密钥，只保存完成 MFA 所需的最小密钥材料。

### 第一阶段：普通 Authenticator 到底在做什么

```text
             第三方网站                            Android 手机
        ╔══════════════════╗                 ╔════════════════════╗
        ║  Microsoft 等网站 ║                 ║   OpenOnion Auth   ║
        ╚════════╤═════════╝                 ╚═════════╤══════════╝
                 │                                             │
                 │ ① 网站随机生成一段秘密 K_site                │
                 │                                             │
                 │ ② QR: otpauth://...?secret=K_site          │
                 ├────────────────────────────────────────────>│
                 │                                             │
                 │                               ③ 扫描、确认账户
                 │                                             │
                 │                                  ┌──────────▼─────────┐
                 │                                  │ 🔒 本地加密 Vault   │
                 │                                  │ 保存网站给的 K_site │

                 │                                             │
        ┌────────▼────────┐                          ┌─────────▼──────────┐
        │ 网站也保存 K_site│                          │ 手机读取当前时间 T │
        └────────┬────────┘                          └─────────┬──────────┘
                 │                                             │
                 │     双方独立计算同一个短码                   │
                 │                                             │
        ┌────────▼─────────────┐                    ┌──────────▼──────────┐
        │ TOTP(K_site, T)      │                    │ TOTP(K_site, T)     │
        │        428 193       │<───── 相同 ───────>│        428 193      │
        └────────┬─────────────┘                    └──────────┬──────────┘
                 │                                             │

```

这里没有数字签名。TOTP 是网站与手机共享 `K_site` 后，对当前时间做 HMAC，
再截成 6/8 位数字。

### SLIP 的“树”和“叶子”是什么意思

```text
                         一个根秘密 S
                              │
             ┌────────────────┴────────────────┐
             │                                 │
             ▼                                 ▼
   ╔══════════════════╗              ╔══════════════════╗
   ║ SLIP-0010 分支    ║              ║ SLIP-0021 分支    ║
   ║ 公私钥 / 数字签名 ║              ║ 对称密钥 / 加密   ║
   ╚════════╤═════════╝              ╚════════╤═════════╝
            │                                  │
      ┌─────┴────────┐                    ┌────┴──────────┐
      ▼              ▼                    ▼               ▼
┌───────────┐  ┌─────────────┐      ┌────────────┐  ┌────────────┐
│账户身份叶子│  │ Agent 身份叶子│      │MFA Vault叶子│  │备份包装叶子│
└───────────┘  └─────────────┘      └────────────┘  └────────────┘
      🔑              🔑                    🔒              🔒

  泄露一个 hardened 叶子，不应让攻击者倒推出父节点或兄弟叶子。
  但泄露最上面的根秘密 S，仍然会暴露整棵树。
```

“叶子节点”只是树末端的一把专用密钥。例如：专门加密 MFA Vault 的叶子。
它不是 TOTP 数字，也不是网站给的 `K_site`。

### 手机到底应该保存什么

```text
          ❌ 不进入手机                         ✅ 手机需要保存
   ┌────────────────────┐                 ┌────────────────────────┐
   │ OpenOnion 账户根秘密│                 │ 网站 TOTP secret 的密文 │
   │ BIP-39 助记词       │                 │ 最小 MFA 加密子树/包装键 │
   │ SLIP-0010 master   │                 │ 硬件保护的设备批准私钥   │
   │ Agent 私钥          │                 │ issuer/account 等元数据  │
   └────────────────────┘                 └────────────────────────┘
                                                      │
                                             Android Keystore
                                             + 生物识别/设备 PIN
```

第三方的 `K_site` 是网站随机给的，所以仅凭助记词无法重新生成。要恢复，必须同时有：

```text
     恢复/解密材料  +  加密后的 Vault 备份  =  原来的 TOTP 凭据
```

```text
 ╚═════╤══════╝                         ╚══════╤═══════╝
       │                                       │
       │ 请求内容                              │ 推送密文
       │ Agent / 网站 / 账户 / 操作 / 过期时间  │
       │                                       ▼
       │                              ╔══════════════════╗
       │                              ║  OpenOnion Auth  ║
       │                              ╠══════════════════╣
       │                              ║ 验证 Agent 签名  ║
       │                              ║ 显示完整操作      ║
       │                              ║ 人脸/指纹批准     ║

       │                                       │
       │                              ┌────────▼─────────┐
       │                              │本地解密 K_site   │
       │                              │计算当前 TOTP     │
       │                              └────────┬─────────┘
       │                                       │
       │                           一次性、绑定本次登录的密文
       │                                       ▼
 ╔═════▼════════╗                      ╔══════════════════╗
 ║ Agent 只看到 ║<──── 结果状态 ──────║ 可信浏览器执行器  ║
 ║ approved/否  ║                      ║直接填入正确网站   ║
 ╚══════════════╝                      ╚════════╤═════════╝

                                      ╚══════════════════╝

    模型不拿 K_site，最好也不拿 6 位数字。

```

## 🔍 KEY POINTS

- `K_site` 是网站凭据；谁复制了它，谁就能独立生成未来的 TOTP。
- SLIP 最有价值的是密钥隔离与恢复，不是替代 RFC 6238。
- 人批准的对象应是完整、签名、短期的操作请求，不是模糊的一句自然语言。
- Phase 0 可以完全离线；网络、Agent 和推送都留到 Phase 1。
- 真正写密码学代码前，先冻结威胁模型、恢复模型和公开测试向量。

## 📦 DEPENDENCIES

Standards:

- RFC 4226 — HOTP
- RFC 6238 — TOTP
- BIP-39 — recovery seed
- SLIP-0010 / SLIP-0013 — signing identities
- SLIP-0021 — symmetric-key hierarchy

Platform:

- Android Keystore / StrongBox
- Android biometric/device authentication

Later protocol:

- ConnectOnion Agent identity
- reviewed OIP encrypted transport
- recipient-bound one-time Secret envelope
